# OC Studio Web：浏览器验收与真机复核（2026-11-19）

分支：`web-dev`。本文件将自动化 CI、浏览器手机模拟和实体设备验收分开说明。

## 自动化验收入口

在 `.github/workflows/web-cloud-check.yml` 的独立 PostgreSQL 16 作业中，完成 Better Auth 登录、数据迁移和 Next.js 构建之后启动测试服务：

- `tests/cloud-graph-layout.test.ts`：验证请求长度、节点类型、重复坐标、UUID、版本号和数值精度。
- `tests/cloud-graph-layout.integration.test.ts`：验证跨库阻断、viewer 只读、旧版本 409、全批同步修订记录，并制造第二节点 SQL 失败来确认首节点完全回滚。
- `scripts/cloud-browser-acceptance.cjs`：使用 Chromium 两个独立浏览器会话（桌面 1366×900、触摸手机视口 390×844）登录、创建测试角色、打开关系图、模拟触摸拖线、从另一会话更新全批布局、验证旧版本冲突、打开时间线导出面板并更改标题和布局密度。
- CI 测试截图：Actions 工件 `cloud-browser-acceptance`。包括移动关系图、时间线预览以及失败现场。

## 验收状态与解释

测试脚本随改动提交。**完成状态以对应 `web-dev` 的 GitHub Actions 最终结论为准**。Chromium 手机模拟包含真实浏览器触摸事件，仍需通过 Android Chrome 和 iOS Safari 真机验证。

## 实机与多设备复核清单

1. Android Chrome：两个角色之间拖动手柄连线、输入关系并提交；长按节点菜单、双指缩放、平移和弹窗不应互相干扰。
2. iOS Safari：重复手柄拖动与两次点按、长按、页面返回和屏幕旋转；检查图片导出与保存。
3. 两个独立账号同时打开同一世界观：A 重排，B 基于旧版本重排应得到 409；B 刷新看到 A 的全部坐标，历史版本没有缺口。
4. 中途断网并恢复：确认一次批量保存的全部节点与修订同时成功或一起回滚；响应遗失时客户端读取数据库真源，不盲目重试。
5. 时间线高级导出：标题、紧凑/标准/稀疏浓度、时期色块、公元前年份、长跨度和空年份事件；检查实际下载的 PNG 图像。
6. 100 / 500 / 1000 节点压力：检查 PostgreSQL 锁等待、保存耗时、浏览器内存、缩放/导出流畅性。

真机验收记录建议包含设备型号、系统版本、浏览器版本、网络场景、屏幕截图和异常重现步骤。
