# OC Studio 关系图 · 上游与 Web 移植逐项对照

对比基准：上游 `Pokanshuu/OC-Studio@main`（`22588336760ac`）及 Fork `Strangeryuu/OC-Studio-web@web-dev`。本文件描述实际源码中已经接入的行为及待实测项目，持续更新，不将 CI 通过自动解释为手机真机验收完成。

## 源码复用情况

- 上游 `src/features/relations/` 目录共 **25** 个原有文件；本轮核对时，Fork 中 **13 个保持完全相同的 Git blob**，其余 **12 个在原件基础上修改适配**。原版没有被另写一套页面替换。
- 完整保留的核心包括 `EdgeStylePanel`、`RelationCreateDialog`、`RelationNodeCreateDialog`、`relation-graph-utils`、`floating-edge`、`export-graph` 与 `export-options`。
- 需要 Web 适配的主文件为 `RelationGraph.tsx`、`RelationEdge.tsx`、三个节点组件、`services.ts`、`layout.ts`、`types.ts` 以及部分工具条；新增云端桥接文件 `cloud/workspace-graph-mutations.ts`、`cloud/WorkspaceGraphExportDialog.tsx`、`mobile-connection.ts`、`components/useTouchNodeMenu.ts`。
- **原版统一导出中心的 `GraphPanel.tsx` 被复用**，云端以 props 注入当前 workspace 的图数据；原版对应面板仍由 Dexie 加载。

## 仍有差距 / 需要完成的验收

1. **手机真机**：触摸拖线、长按节点操作菜单、平移/双指缩放、切换窗口与编辑状态、移动端点击关系线修改样式，分别使用 Chrome Android 与 iOS Safari 验证。
2. **复杂同步**：云端删除节点的跨实体旧引用清理与桌面版 `deleteGraphNode`/各 feature 删除 service 逐项核对；当前云端实体按版本软删除、关系投影会隐藏失效端点，持久化旧引用的清理策略需单独验收。
3. **批量布局一致性**：目前逐实体版本化保存，并保留各自修订。多设备并发或中途网络断开时存在部分写入的可能，事务型批量布局 API 可进一步缩小差距。
4. **高密度性能**：100–1000 节点、长文本、私有头像、并行边、导出缩放的浏览器性能与内存验证。
5. **跨设备回归**：编辑后刷新、跨账号观察更新、撤销布局、回收站恢复与 `.ocbak` 导入导出后布局一致性。

## 操作验收路线（手机端）

1. 使用 editor 或以上角色，打开已有两个角色的关系图，确认四周手柄可见；按住其中一个圆点滑动到另一角色手柄后松开。
2. 弹出原版「添加关系」对话框，选择“朋友”或输入自定义称呼，确认后关系线出现；另一台设备刷新后应看到相同关系。
3. 用同一对节点创建第二条不同名字的关系，检查并行线错开、单条删除不会影响另一条；重复同名应提示重复。
4. 长按节点头像/卡片（约 0.55 秒），在菜单里执行“只看它的关系”或“更换图片”，验证打开图片后正确同步。
5. 用 viewer 角色重复尝试拉线和删除：手柄应只用于显示图形，不允许创建关系。
6. 桌面版验证“重排全部 → 撤销”、大图 PNG 导出和子图导出；再进行两浏览器同一条目的并发修改，确认版本冲突提示与历史记录。
