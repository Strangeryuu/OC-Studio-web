# OC Studio Web：首装初始化、账号、权限与找回密码

本说明适用于 `web-dev` 分支的 Docker / VPS 部署，数据库需要完成 `cloud/migrations/0006_site_accounts.sql` 迁移，运行时配置 `BETTER_AUTH_URL` 与长度足够的随机 `BETTER_AUTH_SECRET`。

## 首次部署管理员初始化

第一次启动前数据库中没有用户且没有 `initialized` 标记时，打开主页 `/` 或登录页 `/login` 会被引导到 `/setup`。在初始化界面填写：

- 管理员用户名：2–100 字符
- 管理员邮箱：有效且唯一的邮箱地址
- 管理员密码：12–128 字符，使用独立强密码

提交后，服务器在 PostgreSQL 事务内获取初始化专用排他锁，原子创建 Better Auth 凭据用户和初始化标记。同一时间多个请求仅有一个成功。初始化完成后 `/setup` 自动重定向登录页面；系统不会生成或公布默认管理员凭据。

**首装安全建议：** 在创建第一个管理员之前，先通过 VPS 防火墙限制管理 IP，或通过 SSH 隧道进行首次设置。公开提供初始化页面之前任何人都可能先占用未初始化的实例。初始化后再开放 HTTPS 访问。

已存在用户的旧数据库不会自动再次进入首装引导；如果历史管理员账号尚未具备平台 `admin` 角色，应在数据库备份后由部署维护人员按迁移方案检查并升级旧账号。

## 权限等级

平台角色从数据库中读取并在每次敏感 API 调用时校验：

| 身份 | 范围 | 权限 |
| --- | --- | --- |
| **平台管理员**（`user.role=admin`） | 整个站点 | 管理所有用户和注册码、配置邮件；查看、创建和修改任何世界观内容，统一进入管理员菜单 |
| **世界观所有者**（`workspace_members.role=owner`） | 自己建立的世界观 | 完全管理该世界观、成员和内容；拥有项目所有权 |
| 世界观管理员（`admin`） | 被加入的指定世界观 | 管理该世界观成员、设置和内容；全站用户管理仍归平台管理员 |
| 编辑者（`editor`） | 被邀请的指定世界观 | 查看及编辑内容、上传素材 |
| 访客（`viewer`） | 被邀请的指定世界观 | 查看资料、提交允许的评论 |
| 普通用户（未加入其他世界观） | 自己创建的世界观 | 可建立并管理自己的世界观；他人的私人世界观对其不可见 |

普通用户可通过世界观邀请成为指定项目的编辑者或访客。平台管理员对各个世界观的访问权限由服务器以 `owner` 等效能力处理，保留资料库真实创建者的所有权记录。

## 平台管理员菜单

平台管理员登录后，顶部导航出现 `/admin` 菜单。普通用户不显示该入口，直接访问页面也会由服务器拒绝。

- **用户管理** `/admin/users`：新建普通用户或平台管理员；设置用户角色；禁用/恢复普通用户。服务端 Better Auth 管理角色包含 `user:set-role` 权限，以支持创建账号时指定角色。
- **注册码管理** `/admin/invites`：生成有有效期及人数上限的注册码、查看使用次数、撤销注册码。注册码随机生成、数据库仅保留 SHA-256 摘要，明文只在创建时展示一次。访客在 `/register` 提交用户名、邮箱、密码、注册码后可创建普通账号。
- **邮件设置** `/admin/mail`：支持本机 Sendmail 或 SMTP 发送重置邮件；普通用户无配置权限。

### 找回密码

在 `/login` 点击“忘记密码？”，输入注册邮箱；如邮件配置正常，用户会收到限时重置链接。点击后进入 `/reset-password` 设置新密码。Better Auth 颁发的重置令牌默认有效一小时，成功修改密码后令牌一次性失效。

- **本机 Sendmail**：需要在运行 Node Web 的主机或容器内配置可工作的 `/usr/sbin/sendmail`；可通过受信任的 `SENDMAIL_PATH` 环境变量指定绝对路径。**仅在 VPS 宿主机装好 MTA 而容器内部没有对应程序时，需要同时提供容器内的执行环境**。
- **SMTP**：填写服务商 SMTP 主机、端口、加密方式、账号和密码。465 通常直接 TLS；587 通过 STARTTLS。TLS 连接校验服务端证书，密码由服务器使用 `BETTER_AUTH_SECRET` 派生密钥进行 AES-256-GCM 加密后存储。变更 `BETTER_AUTH_SECRET` 前必须先安排密钥/邮件设置迁移，否则旧 SMTP 密文将无法解密。

**邮件发送模式都需先用测试邮箱检查实际投递、垃圾邮件情况和重置后的登录。** CI 测试通过本地受控 Sendmail 捕获邮件并验证一次性令牌与密码哈希，不会发送真实互联网邮件。

## 自动化验收与部署检查

`.github/workflows/web-cloud-check.yml` 除类型检查、测试、生产构建外，还包含真实 PostgreSQL 环境的管理员建号、注册码注册、全局权限隔离与本机邮件重置流程。另有独立全新数据库作业验证主页首次跳转、唯一首管理员事务创建、初始化完成后关闭向导。**只有各个前置作业成功才会发布新的 GHCR Docker 镜像。**

上线检查：先运行数据库迁移，完成初始化，登录 `/admin`；创建普通账号验证普通角色；从注册码注册测试账号；用该账号创建世界观并邀请协作者；最后选择邮件模式完成一次真实邮箱重置测试。可以参照 `docs/web-docker-deployment.md` 的 Compose 与备份步骤。
