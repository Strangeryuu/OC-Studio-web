## 源码复用和技术基线

- 上游 `Pokanshuu/OC-Studio@main`：`22588336760a`。Web 移植开始核对时，Fork 的 `main` 亦为此版本。
- 上游 `src/` 682 个文件中，Fork `web-dev` 延续 680 条原路径：630 文件 blob 与上游完全相同，50 文件在复用基础上作了兼容性修改；上游两个 Next.js app 入口改由 Web/原版路由组承载。
- 原版 TipTap 编辑器、MapCanvas、MapGeneratorPanel、NovelReader、TreeRow、关系图 React Flow、TimelineView、树形表格组件、全局相册组件以及各类原版导出纯函数仍在代码中。

## 后续开发顺序（保留源码优先）

1. **安全与交付**：用 `web-dev` 当前 SHA 镜像在隔离 VPS 执行首次部署→创建用户→持久化媒体→升级→完整备份恢复；分别用 owner、editor、viewer 与第二资料库验收权限。
2. **关系图**：源码与原版 25 个文件逐项对照，现已恢复重排撤销、私有换图、原版 GraphPanel 完整导出并扩展手机触摸拖线和长按菜单；下一步以 Android/iOS 真机、两设备并发、版本冲突、删除引用清理、100+ 节点大数据量实测为主。详见[专项验收表](./web-graph-parity-2026-11-19.md)。
3. **时间线**：将 `desktop-extras.periods` 升级成可版本化读写的云端时期存储，恢复原版时期管理及高级导出设置；当前已经直接复用原版 `renderTimelineCanvas` 提供云端 PNG。
4. **小说/模板**：补高级 Word/导出中心与模板复杂块，保持原版 `NovelReader`、`docx` 和模板组件；逐项测试迁移对照。
5. **地图/相册/表格**：针对生成器 Worker、文件 IO、移动手势、复杂模板字段及大数据量做真机验收；缺口定位后再修改适配层。
6. **完整发布验收**：Web/Node、PostgreSQL HTTP、Docker 实际镜像构建、VPS 浏览器与灾备恢复分别记录，所有变更只提交 `web-dev`。

验收规则：自动化 CI 成功与公网/VPS/浏览器手工验收分别记录；没有跑过的功能保持「待验收」。部署脚本更改时应与 Compose 一起手动同步 VPS，应用镜像可继续用 GHCR 自动发布。
