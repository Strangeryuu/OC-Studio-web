# OC Studio Web · 分类归档与增量导入

本功能参考 [OC-editor](https://github.com/nekibud/OC-editor) 的分类备份工作流重新实现，复用现有 PostgreSQL 世界观实体、身份认证与素材权限。

## 使用入口

进入目标世界观 → **备份与迁移** → **分类归档 · 跨世界观迁移**。

- 选择角色、事件、国家或世界词条；角色可按分组过滤，词条可按分类过滤。
- 导出 `.ocbak` JSON 文件。会携带被选中实体以及其关系所需的同资料库实体，并包含关联的私有图片和云端标签。
- 在另一个世界观中选择该文件，先查看来源、条目数、依赖对象、图片数及同名条目数量。
- **跳过同名**：保留目标条目，把其他条目导入，并将关系指向保留的实体。
- **保留两者**：导入同名实体副本，名称自动添加「（导入）」，重新分配 UUID 和数字 ID；已有条目保持原样。

这套增量迁移与整库恢复使用**不同的协议和入口**。完整备份 `version: 1` 仍需空白目标世界观，分类文件 `format: "oc-studio-web-category-v1"` 支持有内容的目标世界观。当前分类导入入口仅接受 Web 分类文件；OC-editor 的 `oc-editor-ocav` 格式仍待单独转换与验收。

## 数据隔离及事务约束

- 导出只读取当前认证用户有 `export:create` 权限的世界观；导入和预览仅开放当前世界观 `workspace:update` 权限（所有者/管理员）。
- 分类导入在单个 PostgreSQL 事务中完成：锁定目标世界观、分配全部实体 ID、复用同名标签、导入图片、重写实体关系与正文 Tiptap 引用、登记新增角色分组和自定义词条分类。
- 用户选择 **跳过** 时，按实体类型 + 标题匹配，同一类词条还区分 `category`；重复匹配不更新已有实体。检测到多条同名目标时会拒绝自动合并。
- 外来媒体必须包含在归档的内嵌图片列表，并重新写入当前世界观的私有媒体库。遇到失败时回滚数据库事务，同时清理已写入的新媒体文件。
- 归档包含内容、头像等私人素材，请妥善保管。数据文件中不应包含鉴权令牌、邮箱或数据库连接信息。
- 任何关系超出已有可解析的同世界观记录，都会返回错误并取消该次导出或导入，优先保护引用一致性。
- 分类归档仅用于角色、事件、国家与设定词条；地图和小说具有特殊实体语义，继续通过对应模块或完整备份迁移。

## 当前限制与下一阶段

1. 最大文件约 40 MB、500 条实体和 100 张媒体素材；大世界观可进一步缩小分类范围。
2. 当前可选策略为「跳过同名」「保留两者」。**覆盖**需要预览时的版本快照和导入时逐项版本比对，待独立验收后开放。
3. 自定义分类会在目标缺少同名分类时登记为通用「词条」模板；自定义模板的跨世界观精确复制与重名解决仍需进一步实现。
4. 保留关联的原始数据优先于猜测修复；历史遗留的悬空关系需要先在源世界观处理。
5. 尚需 Android Chrome / iOS Safari 的真实文件保存与选择器验收。
